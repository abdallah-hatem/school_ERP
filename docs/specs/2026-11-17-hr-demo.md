# Spec — Foundation + HR demo (2026-11-17)

Status: **awaiting approval.** Business rules live in `docs/BUSINESS_LOGIC.md` (§ references below).

## Goal

A real, thin first version for the client demo on **Sunday 2026-11-22**, run locally:

1. **Foundation:** the app shell every later module builds on.
2. **HR:** employees, penalties, monthly lateness, and a monthly payroll run.
3. **Settings:** show that the school's rules are data, not code. Change a rule, rerun payroll, and
   the numbers change.

Source of requirements: the HR department's scope page and the staff internal regulations (25
scanned pages, received 2026-11-16). They describe attendance, leave, permissions, contracts and a
large penalty catalogue. **They do not define salary calculation**, so payroll is basic salary minus
deductions (owner's decision, 2026-11-17).

## Intake decisions

| Question | Decision |
|---|---|
| Who uses it | School staff in the HR office (HR manager, HR officer). Desktop first, fully responsive. |
| Platforms | Web only (`apps/web`, Next.js). No mobile app. |
| Backend | NestJS API built in this run (`apps/api`), Postgres via Prisma, `packages/shared` for shared types, keys and locales. |
| Tenancy | One deployment and one database per school (`docs/ARCHITECTURE.md`); no tenant column. |
| Where it runs | Locally for the demo (Docker Postgres). Hosting comes later. |
| Languages | Arabic and English, full RTL. Arabic is the default for this school (GUESS). |
| Theme | Light only. Design direction "Campus" (`design/mockups/b-campus.html`). |
| Roles | One role for the demo: **HR admin** (all permissions). The roles system comes later (§2). |
| Currency | EGP, amounts stored as integers in piastres. |

## Users and roles

- **HR admin** — signs in, manages employees, records penalties and lateness, runs and approves
  payroll, edits settings. Seeded account in `CREDENTIALS.local.md`.

## Entities

Departments · Stages · Job titles · Employees · Penalty catalogue (violations with levels) ·
Penalty records · Monthly lateness entries · Payroll adjustments · Payroll runs and lines ·
Settings · Users. Rules for each are in §3–§7.

## Flows

1. **Sign in** → dashboard (headcount, this month's payroll status, penalties this month).
2. **Employees:** list (search, filter by department, stage, status) → add / edit → profile
   (details, penalties history, payroll history) → deactivate.
3. **Record a penalty:** pick an employee and a violation from the catalogue, plus a date → the
   system shows the repeat level and the action it implies → save as pending → approve or cancel
   with a reason (§4).
4. **Monthly lateness:** for a month, enter each employee's accumulated late / early-leave minutes
   (manual now; fingerprint import later) → the system shows the days deducted (§5).
5. **Payroll:** create the month's run → lines calculated for every active employee → add one-off
   adjustments → recalculate → approve (locks the month) → payslip (print, EN/AR) and bank sheet
   (Excel) (§6).
6. **Settings:** school identity; lateness rule; payroll rule (day divisor, part-time percentages);
   penalty catalogue and repetition window; lists (departments, stages, job titles) (§7).

## The demo story (what Sunday shows)

1. Arabic ↔ English, the whole app flips.
2. Employees list and a profile.
3. Record a repeated violation. The level goes up automatically from the catalogue.
4. Run November payroll. Show the deductions from penalties and lateness.
5. In Settings, change the lateness rule or a penalty's days → recalculate → the numbers change.
6. Approve → print a payslip in Arabic → export the bank sheet.
7. Show it on a phone: the same screens, responsive.

## Out of scope for the demo (Planned, in §8)

Leave, permissions and the employee request portal · fingerprint device integration · recruitment
and job applications · contracts and renewal deadlines · medical and legal workflows · the annual
raise · tax and social insurance · roles and permissions beyond HR admin · reports beyond payroll ·
notifications · hosting.

## Seed data

- One HR admin account.
- The school's name as the default school-name setting (seed only, never in code).
- Lists: stages (Kindergarten, Primary, Preparatory), about 10 departments, about 15 job titles.
- About 40 employees across stages and departments, full-time and part-time, with realistic Egyptian
  names (EN/AR) and salaries.
- The full penalty catalogue from the regulations (4 tables, 72 violations, levels 1–5).
- November 2026: lateness minutes for about 15 employees and about 10 penalty records (some
  repeated), so the payroll run shows every kind of deduction.
