# T12: Penalties screens + profile penalties tab

Branch `feature/t12-penalties-ui` (from `2b18c3d`, rebased on `origin/dev` after T9).
Class: frontend · ui. Date: 2026-11-17.

## What landed

- **Routes** (thin): `app/[locale]/(dashboard)/penalties/page.tsx` (+ `loading.tsx` skeleton) and
  `app/[locale]/(dashboard)/employees/[id]/penalties/page.tsx` (profile → Penalties, inside
  `EmployeeProfileShell`; the existing `[id]/loading.tsx` and `employees/error.tsx` cover it).
- **Module** `modules/hr/penalties/`:
  - `apis.ts` (`"use server"`, on `apiFetch` + `handleResponse`): `GET_PENALTIES`,
    `GET_PENALTY_PREVIEW` (no-store), `CREATE_PENALTY`, `APPROVE_PENALTY`, `CANCEL_PENALTY`,
    `GET_PENALTY_GROUPS`. Reads tagged `hr-penalties` / `hr-penalty-catalogue`; writes revalidate
    `hr-penalties`. Active employees for the picker come from the employees module's `GET_EMPLOYEES`.
  - List: MonthStepper (this month by default, can't go past it), status filter (all / pending /
    approved / cancelled), debounced search (employee name or code, violation — the API's `search`),
    always-visible pagination; all in the URL with `scroll: false`, rows dim while loading. Columns /
    cards: date, employee, violation (localised), level, action + days (deductions in the danger
    ink), status pill (pending = warning, with the warning row bar; cancelled shows its reason),
    row actions. "No penalties this month" (with Record) differs from "No penalties match" (with
    Clear filters); a failed load shows ErrorState + retry.
  - "Record a penalty" dialog: employee picker (active only), violation picker grouped by catalogue
    group in `sortOrder` (retired violations and every violation of a retired group hidden), date
    (today by default, future days disabled + zod rule), note (textarea, 1,000 counter). A live
    preview line from `GET /hr/penalties/preview` whenever employee, violation or date changes
    ("Level 2 — Deduct 0.5 day" + how many earlier approved penalties count); a slower older answer
    never replaces a newer one; a preview error (e.g. retired violation) shows in the line. Saves as
    pending; `EMPLOYEE_INACTIVE` / `VIOLATION_RETIRED` land under their field, anything else
    (`PAYROLL_APPROVED`…) as an alert above the buttons. Double submit blocked.
  - Row actions: Approve (pending only) behind a confirmation; Cancel (pending or approved) through
    `ConfirmDialog` with a required reason; a cancelled penalty has none. A refusal (`PAYROLL_APPROVED`,
    `PENALTY_CANCELLED`, `PENALTY_NOT_PENDING`…) stays in the dialog as the translated
    `errors.<CODE>` message (no toast); the list refreshes when that dialog closes.
  - Profile tab: the employee's penalties across all months, newest first (API order), paged in the
    URL, same row actions, no employee column; "Record a penalty" with the employee pre-picked
    (hidden for an inactive employee).
- `PROFILE_TABS` gained `{ key: 'penalties', labelKey: 'common.nav.penalties', segment: 'penalties' }`.
- **Locales:** `packages/shared/locales/{en,ar}/penalties.json` (identical keys). Error texts come
  from the existing `errors` namespace.

## Doubts

- Every Radix `Select` trigger whose value is the "all" item (status filter here, the employees
  filters, rows-per-page) renders blank in `next dev` until opened — pre-existing (same on the
  employees list), not fixed here.
- The list filters by one month at a time (the stepper); there is no "all months" view outside the
  profile tab. The brief asks for a month filter, so that is what was built.
- Day counts read "Deduct 0.5 day" (the shared `formatDays`) rather than "½ day".
- At ~800 px of content width the table scrolls sideways to reach the actions column; it fits from
  ~1000 px and switches to cards below 740 px.
