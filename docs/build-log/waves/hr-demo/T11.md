## What landed

- **Routes** (thin, `app/[locale]/(dashboard)/employees/`): `page.tsx` (list), `new/page.tsx`,
  `[id]/page.tsx` (profile → Details), `[id]/edit/page.tsx`, a `loading.tsx` skeleton for each and
  one `error.tsx` (ErrorState + retry). Unknown or malformed id → not-found page.
- **Module** `modules/hr/employees/`:
  - `apis.ts` (`"use server"`, on `apiFetch` + `handleResponse`): `GET_EMPLOYEES`,
    `GET_MANAGER_OPTIONS` (active, limit 100), `GET_EMPLOYEE`, `CREATE_EMPLOYEE`, `UPDATE_EMPLOYEE`,
    `DEACTIVATE_EMPLOYEE`, `REACTIVATE_EMPLOYEE`, `GET_DEPARTMENTS`, `GET_JOB_TITLES`, `GET_STAGES`
    (`/stages`, core). Reads tagged `hr-employees` / `hr-employee-<id>` / `hr-lists`; writes revalidate.
  - List: search (debounced 300 ms), filters department / stage / status / work system, always-visible
    pagination, all in the URL with `scroll: false`; rows dim while the next page loads; DataTable
    card view under 740 px. "No employees yet" (with Add) differs from "No employees match" (with
    Clear filters). Filters list hidden departments/stages too (they can still have employees).
  - Form (add / edit, all §3 fields in three sections): manager picker = active employees minus self;
    department / stage / job title pickers show visible items, plus the employee's own hidden item on
    edit (with a hint); salary in EGP held as piastres; contract defaults to 1 Jun – 31 May of the
    current contract year, and on add a changed start moves the end to one year later minus a day
    until the end is set by hand; Egyptian mobile field. Edit sends only changed fields (cleared
    optional → `null`). Server errors `DUPLICATE_NATIONAL_ID`, `DUPLICATE_FINGERPRINT_ID`,
    `INVALID_MANAGER`, `MANAGER_LOOP` land on their field; anything else shows as a form alert.
    Double submit blocked (in-flight guard + busy button kept through the navigation).
  - Profile: header (name, status pill, code · job title · department, Edit, Deactivate /
    Reactivate behind ConfirmDialog — stays open on failure), tab bar with only "Details"
    (`PROFILE_TABS` in `components/employee-profile.tsx`; T12 / T14 append an entry + a route under
    `[id]/`), details cards for every field.
  - `index.ts` front door; `messages.tsx` (`EmployeesI18n` adds the `employees` and `errors`
    namespaces).
- **Locales:** `packages/shared/locales/{en,ar}/employees.json` (identical keys).

## Doubts

- **Deactivate reason:** DESIGN.md says deactivating requires a reason, but the contract's
  `POST /hr/employees/:id/deactivate` takes no body, so the dialog asks for confirmation only.
- **Manager who has since become inactive:** the picker excludes inactive employees, but an
  employee's *current* manager stays listed (like a hidden list item) so an unrelated edit doesn't
  blank it; the edit only sends `managerId` when it changes, so the API doesn't re-check it.
- **Date of birth picker:** the shared calendar has month arrows only, so a birth date decades back
  takes many clicks. A year/month jump in the shared `Calendar` / `DateField` (without native
  selects) is worth a follow-up for T3's owner.
- **Phone:** §3 only says "phone required"; the field enforces an Egyptian mobile (the house rule).
  The API accepts any string up to 30 characters, so seeded or imported landlines would fail the
  form on edit.
- `LIST_ITEM_HIDDEN` doesn't say which list it was, so it shows as a form-level alert.
