# T24 — live grouping in money and minutes inputs (ui)

Branch `feature/t24-live-grouping`, on origin/dev `d67a982`.

## What changed
- Number inputs group thousands **while typing** (`30000` → `30,000`), with the caret kept by digit
  count (building-frontends 1.62.5, forms.md "Formatted numbers"). Backspace right after a comma
  deletes the digit before it (Delete before one, the digit after). Paste groups. Letters are
  ignored, Arabic-Indic digits are read as Latin, leading zeros drop, a second dot / third decimal
  is rejected. Blur completes money to `.00`. The input is LTR in both languages.
- `MoneyField` and `NumberField` share the engine (`FormattedNumberInput` in `fields.tsx`); form
  state is unchanged — integer piastres for money, a number for others. Small fields (days, grace,
  divisor, percentages) look the same as before since they never reach a comma.
- Lateness minutes input uses it too; drafts hold the grouped text, `parseMinutes` already strips
  commas, so the live days preview and "Save all" are unchanged.

## Shared pieces created
- `apps/web/src/shared/lib/grouped-number.ts` — `groupedEdit`, `deleteAcrossComma` (pure).
- `apps/web/src/shared/components/ui/grouped-number-input.tsx` — `GroupedNumberInput`.

## Tests
- `fields.test.tsx`: type 30000 → `30,000`; caret between 3 and 0 + `5` → `350,000`, caret after 5;
  Backspace after a comma; paste 1234567; `12.` keeps the dot; blur → `30,000.00`; letters ignored;
  submitted piastres; Arabic page (Western digits, LTR, Arabic-Indic typing).
- `grouped-number.test.ts`: the pure rules.
- `lateness-board.test.tsx`: minutes group live with the days preview; a minus, dot and letters are
  now ignored (previously typed in and flagged invalid), so the invalid case is only "over 6,000".

## Doubts
- Behaviour change on lateness: `-5`, `1.5`, `12a` can no longer be typed (they become `5`, `15`,
  `12`) instead of being shown invalid. This follows the "letters ignored" rule; the old tests were
  updated accordingly.

## Follow-up: real-browser check
- Reported: Home, ArrowRight, `5` on `30,000` gave `300,005`. Cause found with Playwright: on macOS
  Chromium, Home/End scroll the document while the page is scrolled and leave the caret where it
  is — in every input (reproduced on the plain name field), not only this one. The grouping itself
  was right: with the caret after the `3`, typing `5` gives `350,000`, caret 2.
- Added `apps/web/e2e/10-number-input.spec.ts` (en + ar salary: 30000 → `30,000`; caret 1 + `5` →
  `350,000` caret 2; caret 4 + Backspace → `35,000` caret 2; Tab → `35,000.00`; one lateness minutes
  input in an open month: `1,500`, mid-insert → `12,500` caret 2). It moves the caret with the
  arrow keys.
- `GroupedNumberInput` also drops any queued caret restore on keydown (defensive; restores are
  already synchronous in a layout effect, no requestAnimationFrame).
