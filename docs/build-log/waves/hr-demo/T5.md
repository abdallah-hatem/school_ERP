# T5 — HR lists and employees backend

Branch `feature/t5-employees` from `d9ee427`, rebased on `dev` after T6 (`8fcb6e7`). Class: logic.

## Built

- `apps/api/src/modules/hr/lists/` — `/hr/departments` and `/hr/job-titles` (GET `?includeHidden`,
  POST, PATCH `:id`). There is no DELETE; an item is hidden with `isActive: false`. Both names are
  required (trimmed, not blank). One abstract `ListItemsRepository` / `ListItemsService` serves
  both lists. Each create, and each PATCH that changes something, emits `settings.changed` after
  the write: `scope: 'lists'`, `key` `hr.departments` / `hr.jobTitles`, old and new item
  snapshots (old is `null` on create), the user and the time. An empty PATCH emits nothing.
  `getSelectable(id)` returns 400 `FOREIGN_KEY_VIOLATION` when the item is missing and 400
  `LIST_ITEM_HIDDEN` when it is hidden.
- `apps/api/src/modules/hr/employees/` — `GET /hr/employees` (paginated; filters
  `departmentId`, `stageId`, `status`, `workSystem`; search by code / EN name / AR name, not
  case-sensitive), `GET /:id`, `POST`, `PATCH /:id`, `POST /:id/deactivate`, `POST /:id/reactivate`.
  Responses match the shared `EmployeeSummary` / `Employee` types, with explicit `select` and
  `YYYY-MM-DD` dates. Emits `employee.hired` / `employee.updated` / `employee.deactivated`
  after each write (reactivate emits `employee.updated`).
- Code assignment: one atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING` on the `counters` row
  `employee_code`, in the same transaction as the insert. Concurrent creates queue on that row,
  and a code is never handed out twice (deleted rows don't free their codes).
- Rules: national ID is 14 digits and unique (409 `DUPLICATE_NATIONAL_ID`). Fingerprint ID is
  unique (409 `DUPLICATE_FINGERPRINT_ID`). Keeping your own value on PATCH is fine. Both checks
  run before the write, and a P2002 race is mapped to the same codes. Hire date can't be in the
  future. Salary is an integer number of piastres ≥ 1. The manager must be another active
  employee (400 `INVALID_MANAGER`). Loops are found with one recursive CTE up the chain (400
  `MANAGER_LOOP`). Stage, department and job title must exist and be visible, but only when
  newly chosen, so an employee keeps an item that was hidden after it was assigned. Contract
  dates default to the current contract year (1 Jun – 31 May). A start without an end gets a
  one-year contract. The end must be after the start, and a PATCH checks the merged dates. A
  PATCH can't clear required fields. `code` / `status` in a body → 400.
- Stages are read straight from core's table in `EmployeesRepository.findStage`. Nothing writes
  to them.
- `hr.module.ts` additions, merged with T6's. `EmployeesService` is exported through
  `modules/hr/index.ts`.
- Dependency added: `@nestjs/mapped-types@2.1.1` (`PartialType`). `@nestjs/event-emitter`,
  `EventEmitterModule.forRoot()`, `SettingsChangedEvent` and `test/helpers/as-test-user.ts` come
  from T6, and only T6's copy is kept.

## Doubts

- The history key and value shape for list changes (`hr.departments` with item snapshots) is
  our own choice. core's listener (T4) must accept `scope: 'lists'`, even though the Prisma
  `SettingScope` enum only has `SCHOOL` / `HR`.
- "Not in the future" uses the server's local date. There's no school time-zone setting.
- Deactivate and reactivate are idempotent: repeating one returns 200 with no change and no
  event. The docs don't say what should happen.
- A missing list item or stage returns 400 `FOREIGN_KEY_VIOLATION`. There is no dedicated code.
- Deactivating someone who manages others leaves those links as they are.
