# T13 — Lateness screen

Branch `feature/t13-lateness-ui` from `37274a3`, rebased on `origin/dev` (`6f9132c`, after T2 and
T7). Class: ui.

## Built

- Route `apps/web/src/app/[locale]/(dashboard)/lateness/page.tsx` (thin: locale + `?month=`) and
  `loading.tsx` (skeleton in the grid's shape).
- `apps/web/src/modules/hr/lateness/`
  - `apis.ts` (`"use server"`, on `apiFetch`): `GET_LATENESS(month)`, `PUT_LATENESS(month, body)`
    (revalidates tag `hr-lateness`), `GET_HR_SETTINGS()` (tag `hr-settings`, for T10 to
    revalidate), `GET_ACTIVE_EMPLOYEES(page)`.
  - `load-lateness.ts`: server loader. The list, the HR settings and the departments load in
    parallel. A failed list shows the error state. A failed rule shows a warning and "—" for days
    (minutes can still be saved). A failed department lookup leaves the column as "—".
  - `lateness-screen.tsx`: server component. Resolves `?month` (a missing, malformed or future
    month falls back to this month), nests the `lateness` namespace and keys the grid by month.
  - `lateness-board.tsx`: month stepper (next is disabled past this month; switching with unsaved
    edits asks first; URL change with `scroll: false`, rows dimmed while the next month loads),
    a search over name EN/AR and code (client-side over the month's full list), and the
    `DataTable` (table ≥740px, cards below). There is one minutes input per row and a live days
    column. Invalid rows get a red bar, `aria-invalid` and an inline message, and Save all is
    disabled while any row is invalid. Save all ("Save all (n)") sends only the changed rows, has
    a busy state and can't be clicked twice. It shows a translated success toast. A 409
    `PAYROLL_APPROVED` turns the month read-only: banner, "locked" pill, inputs disabled, Save
    hidden, unsaved edits dropped. The toolbar shows a live summary (employees · minutes · days)
    and the current rule in words. Client-side pagination (20/50/100) is always visible.
  - `lateness-entries.ts`: pure grid state (`parseMinutes`, `viewEntry`, `gridState`,
    `matchesSearch`). Days come only from the shared `latenessDays` with the rule from
    `GET /hr/settings`.
- Locales `packages/shared/locales/{en,ar}/lateness.json` (identical keys).

## Doubts

- **Lock is known only after a save.** `GET /hr/lateness` has no `locked` hint, and payroll runs
  (T9) have no month filter. The screen goes read-only on the 409 `PAYROLL_APPROVED`, as the brief
  allows. Suggestion: add `locked: boolean` to the GET (e.g. in `meta`) so the page opens
  read-only.
- **Department** isn't in the lateness rows (`EmployeeRef`). It is looked up from
  `GET /hr/employees?status=ACTIVE` (100 per page, up to 20 pages). Adding `department` to the
  lateness row would save that call.
- The API keeps its own `isMonth` in `apps/api/src/common/utils/dates.util.ts`. It could now
  import the shared one; I left it alone because it is outside T13's scope.
