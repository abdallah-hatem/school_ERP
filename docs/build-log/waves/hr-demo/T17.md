# T17 — Smoke specs (Playwright)

Branch `feature/t17-smoke` from `84afa8f`, rebased on `origin/dev`. Class: logic (e2e).

## Built

- **Location: `apps/web/e2e/`** (not a root `tests/e2e/`), config `apps/web/playwright.config.ts`,
  `@playwright/test` 1.64.1 as a web dev dependency (uses the installed Chromium 1248).
- **`pnpm smoke`** (root) → `scripts/smoke.sh`, which owns the whole stack:
  1. drops and recreates `school_erp_e2e_18` (`scripts/e2e-db.sh 18`, migrations applied)
  2. seeds it with `ts-node` (generic fallback when `prisma/seed-data.local/` is absent, as on CI)
     with a `SEED_ADMIN_PASSWORD` and `JWT_ACCESS_SECRET` generated for that run only
  3. builds shared, the API (`nest build`) and the web app (`next build`, `BASE_URL` = the API)
  4. starts the API on 4180 and `next start` on 4181, waits for `/health` and `/en/login`
  5. runs Playwright, prints the summary and failures, stops both servers by PID (trap on exit)
  Ports and DB number can be overridden (`SMOKE_API_PORT`, `SMOKE_WEB_PORT`, `SMOKE_DB`); it
  refuses to start if a port is busy. Extra args go to Playwright (`pnpm smoke 03-penalties`).
  Full logs: `apps/web/e2e/.logs/`. Screenshots: `apps/web/e2e/screenshots/<project>/`. Both
  git-ignored, with Playwright's `e2e/.results/`.
- Two projects: `desktop-en` (1440×900, specs 01–05) and `phone-ar` (390×844, touch, spec 06).
  One worker, file order: the flows build on each other (03's penalty shows in 05's payroll).
- Every spec signs in through the login page as the seeded admin. No saved sessions.
- Support (`apps/web/e2e/support/`):
  - `i18n.ts` — `t(locale, key, values)` reads `packages/shared/locales`, so elements are found
    by role + the app's own accessible names and survive wording changes (T19).
  - `api.ts` — a signed-in API client the specs use to read the state they meet (which employee
    has a prior approved penalty, the run's lines) instead of assuming the seed.
  - `ui.ts` — `signIn`, `shoot` (screenshots), `expectNoHorizontalScroll`, `searchField`.
  - `dates.ts` — today / current month from the clock, never a fixed date.

## Specs (6/6 passing)

1. `01-sign-in` — sign in → dashboard headcount tile shows the API's active headcount.
2. `02-employees` — list → search by code → profile → Edit → new phone → saved (screen + API).
3. `03-penalties` — finds an active employee + violation where a penalty dated today previews
   as level 2 with a day deduction (asks the preview endpoint over the approved penalties; if
   none fits, records and approves a level-1 one first) → record dialog preview shows "Level 2"
   → save as pending → approve → listed as approved at level 2 (and the API agrees).
4. `04-lateness` — 75 and 130 minutes for two employees in the current month → days shown
   (shared `latenessDays`) → save → reload keeps the minutes and days.
5. `05-payroll` — cancels the month's pending penalties (they block approval) → opens the
   current month's run, or creates it → recalculate → the penalised line shows the penalty
   deduction → Settings → HR rules: grace +30 → recalculate → the late line's lateness falls and
   its net rises (screen + API) → approve → payslip shows the approved net and the penalty →
   bank sheet downloads as `.xlsx`. Grace restored in `afterAll`.
6. `06-arabic-phone` — `/ar` dashboard, employees (card view, table hidden) and the payroll run:
   `dir="rtl"`, `lang="ar"`, `scrollWidth === clientWidth`.

Both the "open the existing run" path (seeded November run) and the "create the run" path (run
deleted after seeding, one-off check) passed.
