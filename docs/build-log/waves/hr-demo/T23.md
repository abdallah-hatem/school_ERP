# T23 — Small fixes (class ui + one backend rule)

Branch `feature/t23-small-fixes`, based on `origin/dev` d67a982 (rebased over T22 #33 and #34).

## Items
1. **No rows-per-page, 10 a page.** The shared `Pagination` lost its page-size select (and the
   `onLimitChange` / `limitOptions` props); every caller dropped its own copy (runs list, run lines,
   penalties list and profile tab, payroll profile tab, lateness, settings lists, change history).
   `PAGINATION.defaultLimit` is now 10, so every API list defaults to 10 too (contract line updated).
   The employees card grid keeps T22's 12 (`EMPLOYEES_PAGE_SIZE`, untouched).
2. **Toasts top-right** in both languages, just below the top bar (`offset` 76 / `mobileOffset` 72) so
   they never cover the language switch.
3. **Skeletons match the content.**
   - `DataTable`'s skeleton is now the real table and cards with placeholder cells (`column.skeleton`,
     default one text line in the cell's own line box): same header, widths, paddings, row heights and
     pagination bar (its summary a bar while loading).
   - Route skeletons render the screen itself in a loading state: `RunsList`, `PenaltiesList`
     (`rows` undefined) and `LatenessBoard` (`rows`/`rule` undefined), controls disabled; they read the
     URL (month, filters, page). The run page skeleton reuses the run's own `RunTiles`,
     `RunLinesToolbar`, column layout (`runColumn`) and `RulesPanel` (loading shape). The payslip skeleton
     mirrors the A4 card. Dashboard tiles take value/sub placeholders of the loaded height.
   - Settings School and HR rules draw the real form with the §7 defaults behind `SkeletonMask`
     (every control a pulsing block, labels kept, inert). Catalogue: first group open, as loaded.
   - Payroll routes moved into route groups (`payroll/(list)`, `payroll/[id]/(run)`): the list's
     `loading.tsx` used to wrap the run and payslip pages, so a hard load of a run showed the runs-list
     skeleton first.
   - Measured loading (server first paint, JS off) vs loaded per route at 1440 EN and 390 AR: dashboard,
     lateness, payslip, school / HR rules forms match to the pixel; run page header, tiles, toolbar and
     header row match. Remaining differences are data the skeleton can't know: row count (a page of 10
     placeholders vs fewer runs/stages), the pending-penalties notice, text that wraps onto extra lines.
   - Fixed while measuring: list actions (Rename / Hide) and the run's approved actions (adjust +
     Payslip) wrapped onto two lines; they stay on one now.
4. **Work start / end dropdowns**: Settings → School offers 05:00 … 20:00 every 30 minutes, labelled in
   the locale's time format (`7:30 am` / `7:30 ص`); a stored value outside the range is still listed.
   API: `IsWorkTime` (HH:mm on a 30-minute boundary) → 400 `VALIDATION_FAILED`. Docs: §7 DECIDED
   (owner 2026-11-17), recent changes, contract note on `PATCH /settings/school`.
