# T15 — Dashboard screen

Branch `feature/t15-dashboard-ui` from `98c6da8`, rebased on `origin/dev` (no new commits). Class: ui.

## Built

- Route `apps/web/src/app/[locale]/(dashboard)/page.tsx`: replaces the placeholder (thin: locale,
  then `DashboardScreen`).
- `apps/web/src/modules/hr/dashboard/`
  - `apis.ts` (`"use server"`, on `apiFetch`): `GET_HR_DASHBOARD()` → `GET /hr/dashboard`
    (tag `hr-dashboard`).
  - `load-dashboard.ts`: server loader. It returns the `HrDashboard`, or `null` when the request
    fails, and `null` shows the error state.
  - `dashboard-screen.tsx`: server component. It nests the `dashboard` namespace. The greeting
    renders at once and the figures stream in behind a `<Suspense>` skeleton. There is no route
    `loading.tsx` on purpose: at the `(dashboard)` group root it would also wrap every nested
    screen.
  - `dashboard-view.tsx`: the greeting is the page title, with the school's name from
    `useSchoolBranding` and the month. Four tiles: active headcount (the feature tile, with a
    by-stage breakdown); this month's payroll (net plus a Draft/Approved pill and "Open the run",
    or "No run yet · Create run"); pending penalties; approved penalties. Each tile links to its
    screen. Quick links: Add employee, Record a penalty, Enter lateness, Run payroll, Settings.
    The tiles are 1 column under 360px, 2 on phone and tablet (2×2) and 4 at ≥1280px. The error
    state has a retry (`router.refresh`), and the quick links still work while the figures are
    down. The skeleton has the same shape (four tiles, five link slots).
  - `dashboard-links.ts`: every target URL in one place. Penalties use `?month&status=PENDING|APPROVED`
    (the T12 list's URL filters). Lateness uses `?month`. Payroll goes to `/payroll`. Then
    `/employees/new` and `/settings`.
- Locales `packages/shared/locales/{en,ar}/dashboard.json` (identical keys; a test checks this).

## Doubts

- **No run id on the dashboard.** `currentRun` is `{ month, status, net }` without an `id`, so
  the payroll tile and "Run payroll" go to the runs list (`/payroll`), not the run page. Adding
  `id` to `currentRun` would allow a direct link once T14's run route is known.
- **"Record a penalty"** opens the penalties list (`/penalties`). T12 has no URL parameter that
  opens the record dialog. A `?record=1` there would let the dashboard open it directly.
- The penalty month in the links is `currentRun.month`, else this month from the server clock
  (`monthOf(new Date())`, the same helper the API uses).
