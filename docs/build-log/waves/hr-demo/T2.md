## Built

**API — `core/auth`, `core/users`**
- `POST /auth/login` (`@Public`, 200) → `{ user }`; `POST /auth/refresh` (`@Public`, 200) →
  `{ user }` and rotated cookies; `POST /auth/logout` (signed in) → `{}`, cookies cleared and the
  refresh family revoked; `GET /auth/me` → `{ id, email, name, role }`. No sign-up route (§2).
- Access token: HS256 JWT (`sub`, `role`), 15 min. Refresh token: 48 random bytes, stored as a
  SHA-256 hash in `RefreshToken`, 14 days, rotated on every use, grouped by `familyId` (one sign-in).
- Reuse rule: a rotated token reused **within 30 s** gets a new pair in the same family (parallel
  requests refreshing with one cookie); reused **after** 30 s → 401 and the whole family is revoked.
- Tokens only travel in httpOnly cookies (`auth_token`, `refresh_token`; `SameSite=Lax`, `Secure` in
  production, refresh cookie path `/auth`), never in a body. The API also accepts them as a bearer
  header, which is how the web server forwards them. Cookies are written by
  `AuthCookiesInterceptor` from the controller's `IssuedSession` / `ClearedSession` return value
  (no `@Res()`).
- `jwt` passport strategy replaces the placeholder: verifies the token, then loads the user and
  refuses one deactivated since sign-in.
- Wrong password, unknown email and inactive user give the same 401 `INVALID_CREDENTIALS`; an
  unknown email still runs one bcrypt compare (dummy hash) so timing gives nothing away. Emails are
  matched case-insensitively.
- `FilesAccessMiddleware` on `files/*`: `/files/logo/…` is public, every other `/files/…` needs a
  signed-in active user — whether files are served by a controller or static middleware.
- Config (fails at boot): `JWT_ACCESS_SECRET` (required, ≥ 32 chars), optional
  `JWT_ACCESS_TTL_SECONDS`, `REFRESH_TOKEN_TTL_DAYS`, `REFRESH_REUSE_GRACE_SECONDS`, `COOKIE_SECURE`.
  `.env.example` updated; `test/setup-env.ts` sets a throwaway secret for e2e.
- Seed: `prisma/seed/admin.ts` upserts `admin@school.local` (HR_ADMIN) with the password from
  `SEED_ADMIN_PASSWORD` (required, ≥ 12 chars, no default); wired into `prisma/seed/index.ts`.
  The local login is in `CREDENTIALS.local.md` (ignored by git).

**i18n error layer**
- `AllExceptionsFilter` now translates `message` from the stable `error` code by
  `Accept-Language` (q-weights and regional tags handled; default Arabic). Codes without a
  translation (raw Prisma codes) keep their message. Validation failures add `details: string[]`
  (the raw class-validator messages) to the envelope.
- Messages moved from `common.json` → `packages/shared/locales/{en,ar}/errors.json` (the shared
  test now checks every `ErrorCode` there).

**Web**
- `src/proxy.ts` (Next 16's name for `middleware.ts`) → `core/auth/proxy.ts`: locale prefix
  (`lang` cookie, else `ar`); signed out on a protected page → `/<locale>/login?next=…`; signed in
  on `/login` → `homeFor(role)`; expired access + valid refresh → refreshed **in place** (new token
  forwarded to the same request, both cookies set on its response); failed refresh → login with
  the cookies cleared.
- Sign-in page `app/[locale]/(auth)/login` → `core/auth/components/LoginPage` + `LoginForm`:
  Campus card, EN/AR, language switch keeping `next`, school name + logo from `GET
  /settings/school` with a plain fallback (product name + initials) on any failure; translated API
  error inline; button disabled while pending; email kept after a failed attempt; safe `next`
  (no open redirect).
- `core/auth/apis.ts` (`LOGIN`, `LOGOUT`, `GET_ME`, `GET_LOGIN_BRANDING`), `actions.ts`
  (`signIn`, `signOut(locale)` for the shell's sign-out button), `session.ts` (`getSession()` for a
  layout's first paint), `paths.ts` (`homeFor`, `loginPathFor`, `safeNextPath`).
- `lib/api.ts`: new `forwardAuthCookies` option (mirrors the API's Set-Cookie onto this origin);
  the inline refresh uses the shared cookie helper. `lib/middlewareFunctions.ts`: cookie names from
  shared, `authCookie`/`sessionCookies`, Set-Cookie parsing, `refreshTokens` reads the rotated
  cookies, `decodeJwtPayload`/`isAccessTokenLive`. `app/api/auth/refresh/route.ts` (fallback for a
  render that hits a 401). `next.config.ts`: `/files/*` rewritten to the API so the logo loads.
