# T10: Settings screen

Branch `feature/t10-settings-ui` (from `6f9132c`, rebased on `origin/dev` at `98c6da8`). Class:
frontend · ui. Date: 2026-11-17.

## What landed

- **Route** `app/[locale]/(dashboard)/settings/page.tsx` (thin) → `modules/settings` `SettingsPage`.
  Section in `?section=` (`school`, `structure`, `lists`, `hrRules`, `catalogue`, `history`).
  ≥768px: side list of sections beside the open one; phone: the list first, then the chosen
  section with "All settings" to go back.
- **`modules/settings/apis.ts`** (`"use server"`, on `apiFetch`): school settings GET / PATCH, logo
  upload (multipart `file`), history (paged), stages / departments / job titles (one `ListKind`
  switch, `includeHidden`), HR settings GET / PATCH, penalty groups and violations (GET, POST,
  PATCH). Every mutation revalidates its tag plus `settings-history`; school saves revalidate the
  shell's `school-settings` tag.
- **Sections**
  1. *School*: names EN/AR (≤ 200), default language, work start / end (`HH:mm`, end after start),
     working days (toggle chips, at least one). Sends only changed keys. Logo card: PNG / JPG / SVG
     ≤ 2 MB checked on the client, preview, upload. Name and logo saves call `setBranding`, so the
     shell changes at once.
  2. *School structure* and 3. *HR lists*: one `ListManager` (add, rename, hide / show, no delete),
     DataTable with pagination (the API returns the whole list; paged on the client).
  4. *HR rules*: grace, hour steps editor (add / remove, quarter days, hours numbered 1..n on save),
     extra-hour days, live example ("90 minutes → 0.75 days", editable minutes) computed with the
     shared `latenessDays`; day divisor 1–31; part-time % 1–100; repetition window. Sends only
     changed keys.
  5. *Penalty catalogue*: groups (collapsible; add, rename, retire with confirmation, restore) →
     violations (add / edit dialog, retire / restore) → 1–5 levels (action select, days enabled
     for DEDUCT_DAYS / INVESTIGATION only), validated live with the shared `levelDaysProblem` /
     `violationLevelsProblem`.
  6. *Change history*: paged table — what (translated key), old → new (weekdays, steps, names,
     percentages, enums translated), who, when.
- **Behaviour**: inline translated errors (zod messages are keys); Save disabled while unchanged,
  invalid or saving (busy, one request on double click); "Saved." status line. Unsaved edits: a
  confirm before switching section or following an in-app link, and the browser prompt on
  reload / close.
- **Locales** `packages/shared/locales/{en,ar}/settings.json` (identical keys).

## Doubts

- The EN / ع switch is a button, not a link, so it isn't caught by the unsaved-changes guard:
  switching language with edits loses them without asking.
- `common.json` (ar) work-system labels use Arabic-Indic digits (`٣ أيام`), against DESIGN.md's
  Latin-digits rule (not changed here).
- Retiring a group doesn't flip its violations' `isActive` (the API treats them as retired through
  the group); the screen hides their actions and says so.
- The logo upload was verified by component test only; the live check couldn't pick a file.
