## What landed

  placeholder) with `loading.tsx` and `error.tsx`; `payroll/[id]/page.tsx` (+ `loading.tsx`);
  `payroll/[id]/payslip/[lineId]/page.tsx` (+ `loading.tsx`); `employees/[id]/payroll/page.tsx`
  (profile → Payroll inside `EmployeeProfileShell`).
- **Module** `modules/hr/payroll/`:
  - `apis.ts` (`"use server"`): `GET_PAYROLL_RUNS`, `CREATE_PAYROLL_RUN`, `GET_PAYROLL_RUN`
    (`search`, `departmentId`, `flagged` — filtered by the API), `RECALCULATE_PAYROLL_RUN`,
    `APPROVE_PAYROLL_RUN`, `ADD_PAYROLL_ADJUSTMENT`, `REMOVE_PAYROLL_ADJUSTMENT`, `GET_PAYSLIP`,
    `GET_BANK_SHEET` (file). Reads tagged `hr-payroll-runs` / `hr-payroll-run-<id>`; writes
    revalidate them plus `hr-dashboard`, and approve also `hr-lateness` (the month locks).
  - Runs list: month (link), status pill, employees, net, approved date; always-visible pagination in
    the URL (`scroll: false`). "Create run" dialog with the month stepper (this month or earlier);
    409 `PAYROLL_RUN_EXISTS` is shown inside the dialog; success opens the new run.
  - Run page (as the mockup): title "Payroll · month" + status, Recalculate / Export bank sheet /
    Approve; four tiles (employees with ready/needs-review, salaries, deductions & penalties with the
    split, net to pay = the feature tile, first on phones); table → cards below 740px with salary,
    penalties, lateness, adjustments (signed), net, status (Ready / Needs review + the flags
    `NET_FLOORED`, `PENDING_PENALTIES`) and actions; search (debounced), department filter and a
    "Needs review only" switch, all in the URL and filtered by the API; "no employees match" differs
    from "no employees in this run". "Rules applied this month" panel from `GET /hr/settings` (day
    divisor, part-time %, lateness rule text, penalties window, net floor) with a link to settings;
    beside the table on wide containers, below it otherwise.
  - Approve: confirmation dialog, never disabled by client logic; a refusal (409
    `PENDING_PENALTIES`…) shows as an alert on the page with the code's text in the page language.
    After approve the run is read-only: Recalculate / Approve hidden, bank sheet enabled (xlsx
    download), payslip link on every line, adjustments viewable read-only.
  - Adjustments dialog per employee: list; on a draft add (type, amount in EGP → piastres, reason —
    all required, zod messages translated) and remove; double submit blocked; the returned run
    replaces the page data (with filters on, the lines are refetched).
  - "Adjustments not applied" card: adjustments whose employee is no longer in the run (§6 GUESS).
    With filters on, the loader also reads the unfiltered run to know every employee in it.
  - Payslip print view: school name/logo, month, employee snapshot, salary for the month, day value,
    every penalty incl. zero-amount ones with level, action, days and its share, the share note,
    penalty total, lateness minutes/days/amount, adjustments with reasons and totals, net (and the
    floored note). Print button; `@page A4`, the shell's sidebar/top bar/language row are `no-print`.
    A draft run's payslip URL shows "No payslip yet" + back link.
  - Profile tab: the employee's line in each of the last 24 runs (newest first), payslip link once
    approved, "Open run" while draft.
- **Locales:** `packages/shared/locales/{en,ar}/payroll.json` (identical keys).

## Differences from the contract / doubts

- The contract's payslip `adjustments` has no "applied" flag; "not applied" is derived on the run
  page (adjustment's employee not among the run's lines). Their employee's name isn't in the
  response (no line), so the card says "Employee no longer in this run". An `employee` ref on
  `PayrollAdjustment` would let it name them.
- No API route lists one employee's lines across runs; the profile tab reads the last 24 runs and
  asks each for `search=<code>` (N+1 requests). A `GET /hr/employees/:id/payroll-lines` would
  replace it.
- The API's error `message` follows the `lang` cookie, not the page's locale (an `/en` page with no
  cookie got Arabic messages); payroll screens show `errors.<CODE>` in the page language instead.
  Toasts from `handleResponse` elsewhere still show the server text.
- The rules panel shows today's HR settings; an approved run's numbers were calculated with the
  settings of its approval day (no settings snapshot on the run).
- `next start` uses secure cookies (production); fine on `localhost` only.
