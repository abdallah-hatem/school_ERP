# T19 — Polish: known gaps before the UI audit

Branch `feature/t19-polish` from `84afa8f`, rebased on `origin/dev`. Class: ui, plus a little backend
logic. No schema change and no new migration.

## Built (one item per brief point)

1. **Error language follows the page.** `apiFetch` now sends `Accept-Language` set to the page's
   `[locale]` instead of the `lang` cookie. The locale comes from `x-pathname`, which the proxy now
   forwards on every page it lets through, the login page included. If that is missing it uses the
   referer, then the cookie, then Arabic. This is `requestLocale` / `localeFromPath` in
   `shared/lib/i18n.ts`. The API reads only `Accept-Language` and never the cookie. A filter spec
   pins this down.
2. **Dashboard.** `GET /hr/dashboard` `currentRun` now includes `id`. When a run exists, the payroll
   tile and the "Run payroll" quick link open `/payroll/<id>`. With no run they still go to the runs
   list.
3. **Employee payroll history.** New route `GET /hr/employees/:id/payroll-lines?page&limit`
   (`EmployeePayrollController` in `payroll/`) returns
   `{ runId, lineId, month, status, net }`. Lines come newest month first, `net` comes from the line
   snapshot, and the result is paginated. An unknown employee gives 404. The profile Payroll tab
   makes one request for this, with the page and limit in the URL (`scroll: false`). The old loop of
   one request per run, 24 runs deep, is gone.
4. **Adjustments.** Each adjustment in the run response now has `applied`, `employeeCode`, `nameEn`
   and `nameAr`. `applied` is computed against every line in the run, whatever the line filters.
   The run page lists unapplied ones as "Not applied — <name> (<code>) is no longer in this run".
   The web no longer reads the run a second time to work out who is in it, so the
   `runEmployeeIds` prop is gone.
5. **Rules panel on an APPROVED run.** It is now titled "Current rules" and says "This run was
   calculated on <approvedAt>. These are today's settings and may differ…". On a draft it still
   says "Rules applied this month".
6. **"All" selects.** `FilterSelect` and the rows-per-page select now pass the selected label to
   `SelectValue`. Radix only knows an item's text after the list has mounted, so before this the
   closed trigger was blank, including on the server render. The penalties status filter was a
   hand-made copy of this select and now uses `FilterSelect`.
7. **Penalties table fits.** Level now sits inside the action column ("Level · action"), and the
   other minimum widths are tighter. `DataTable` has a new `cardsBelow` prop (740 / 960 / 1100).
   The penalties list switches to cards below a 1100px container, and the profile tab (which has no
   employee column) below 960px. Neither scrolls sideways any more.
8. **Language switch vs Settings guard.** New `shared/lib/leave-guard.ts`
   (`setLeaveGuard` / `requestLeave`). The EN/ع switch now goes through `requestLeave`. While
   Settings has unsaved edits, `useLeaveGuard` registers a guard, so the switch opens the same
   "Leave without saving?" dialog. Cancel keeps both the language and the edits. Discard switches
   language.

Contract updated in `docs/specs/2026-11-17-hr-demo.md`: the Accept-Language rule, the new route,
the adjustment shape and `currentRun.id`.

## Doubts

- The history route returns only the fields in the brief. The profile tab therefore dropped its
  month salary, deductions, adjustments and flags columns and now shows month, status, net and a
  link. If those columns are wanted back, the route needs to return them.
- `cardsBelow` 1100 means the penalties list shows cards on a 1280px laptop with the full sidebar,
  where the content area is about 950px. The UI audit (T18) should confirm this is acceptable.
- Not checked in a running app. The UI audit will cover it.
